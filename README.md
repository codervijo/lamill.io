# lamill.io

**🌐 Live site → [lamill.io](https://lamill.io)**

Marketing / landing site for **LaMill** — an engineering studio (full stack,
Linux, hardware bringup, IoT, web systems) — plus a [`/work`](https://lamill.io/work) portfolio of case studies,
[`/notes`](https://lamill.io/notes) technical writing, and a small "AI Tools" sub-app
under [`/aitools`](https://lamill.io/aitools).

## Stack

- **TanStack Start** (SSR) — `@tanstack/react-start` + `@tanstack/react-router`
  (file-based routing), on **Vite** with **nitro** as the server builder
- **React 19** + **TypeScript**
- **Tailwind CSS v4** + **shadcn/ui** (Radix primitives in `src/components/ui/`)
- Package manager: **pnpm**

> The current design was generated in [Lovable](https://lovable.dev) and absorbed
> into this repo on 2026-06-28, replacing the previous React 18 + Vite + React
> Router SPA. See `AI_AGENTS.md` for the full agent-facing context.

## Develop

Builds run through the parent Makefile (`sites/Makefile`) inside the Docker dev
container — don't run pnpm directly on the host. From `sites/`:

```sh
make buildsh                 # enter the docker dev container
make run proj=lamill.io      # pnpm install + pnpm dev (vite dev)
make test proj=lamill.io     # pnpm install + pnpm build
```

Host equivalents (per `package.json`): `pnpm install`, `pnpm dev`, `pnpm build`,
`pnpm preview`, `pnpm lint`, `pnpm format`.

> `pnpm-workspace.yaml` in this dir makes lamill.io its own pnpm workspace root.
> Without it, `pnpm install` walks up to `sites/pnpm-workspace.yaml` and installs
> nothing here (no-ops with "resolved 1"). Native install scripts (esbuild,
> `@tailwindcss/oxide`) are allow-listed there too.

## Extensions data contract

The `/extensions` hub renders entirely from **`src/content/extensions.json`**,
which Tabmill generates. The zod schema in `src/lib/extensions.ts` is the
contract; invalid entries are logged at build time and skipped (they don't
break the build).

The file is a top-level JSON **array** of entries:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `slug` | string | yes | Kebab-case (`^[a-z0-9-]+$`); URL is `/extensions/<slug>`. `support` and `privacy` are reserved. |
| `name` | string | yes | Display name. |
| `pitch` | string | yes | One line; directory card + detail page + meta description. |
| `store_url` | URL \| null | no | Chrome Web Store listing. Omit or `null` while not in the store — pages show "In development" instead of an install button. |
| `tool_page_url` | URL | yes | Full tool page on the portfolio site — linked prominently from every hub page. |
| `permissions` | `{name, reason}[]` | no (`[]`) | Every manifest permission, with a plain-language reason. |
| `data_collected` | string[] | no (`[]`) | What leaves the browser, one item each. Shown on the extension page; Tabmill's release lint keeps it empty while the shared privacy policy promises nothing is collected. |
| `analytics` | boolean | no (`false`) | Whether the extension sends usage analytics. |
| `changelog` | `{version, date, notes}[]` | no (`[]`) | `date` is `YYYY-MM-DD`; any order, rendered newest first. |
| `status` | `"published"` \| `"unlisted"` \| `"draft"` | no (`"draft"`) | Drafts are hidden from `/extensions` and 404 at their URLs. Unlisted entries are hidden from `/extensions` and the sitemap, but their page is live with `noindex` — Tabmill exports every not-yet-published extension this way. |

```json
[
  {
    "slug": "save-page-pdf-md",
    "name": "…",
    "pitch": "…",
    "store_url": "https://chromewebstore.google.com/detail/…",
    "tool_page_url": "https://…",
    "permissions": [{ "name": "activeTab", "reason": "…" }],
    "data_collected": [],
    "analytics": false,
    "changelog": [{ "version": "1.0.0", "date": "2026-10-03", "notes": "…" }],
    "status": "published"
  }
]
```

Adding a published entry also needs `/extensions/<slug>` added to the
hand-maintained `public/sitemap.xml`.

## Extensions privacy contract

One privacy policy covers every extension: **`/extensions/privacy`**, rendered
from **`src/content/privacy.json`**, which Tabmill generates from its
`privacy-policy.yaml` (Tabmill D-036). Every Chrome Web Store listing links
there. The zod schema is in `src/lib/privacy.ts`:

| Field | Type | Notes |
| --- | --- | --- |
| `version` | positive int | Bumped whenever what the policy promises changes; the page shows "Policy version N" and Tabmill's release lint checks the live page for it. |
| `updated` | `YYYY-MM-DD` | Shown as "Last updated". |
| `permissions` | `{ [name]: reason }` | Every permission a LaMill extension may request. Tabmill blocks a release that needs one not listed here. |

The page states nothing is collected, no analytics, no remote code. Tabmill's
release lint fails any extension that would make one of those untrue.

## Extension landing pages

`/extensions/<slug>` renders the Tabmill facts above plus an optional,
**lamill-owned** copy file — Tabmill exports never touch it. Without a copy file
the page stays short (install, permissions, changelog, tool-page link).

To give the next extension a full landing page:

1. **Copy file** — `src/content/extension-pages/<slug>.ts`, default-exporting an
   `ExtensionPageInput` (schema: `src/lib/extension-pages.ts`). Copy
   `save-page-pdf-md.ts`: title/H1/meta description, value prop, facts row,
   optional hero `video` (silent MP4 + YouTube id/title/description/uploadDate),
   `steps`, `gallery` screenshots, body `sections`, `faq`, outbound `links`,
   `ogImage`. Only facts the operator supplied — nothing invented.
2. **Media** — drop the source files into `public/extensions/<slug>/`
   (`*silent*.mp4`, `shot-*.png`), then on the **host** (needs ffmpeg +
   ImageMagick, not in the dev container):

   ```sh
   bash scripts/ext-media.sh <slug> [og-source.png]   # default og source: shot-before-after.png
   POSTER_AT=2 bash scripts/ext-media.sh save-page-pdf-md   # poster frame in seconds (default 0)
   ```

   Once the `.web.mp4` exists, delete the source MP4 from `public/` (it would deploy
   unused) — keep the original backed up outside the repo. Re-runs without it still
   refresh the poster, AVIF/WebP, OG and manifest.

   It writes a 720p `<name>.web.mp4` (point the copy file's `video.src` at it)
   with its poster (first frame), AVIF/WebP per screenshot, a 1200×630
   `og.png`, and every file's pixel size into `src/content/extension-media.json`.
   A media item missing from that manifest is hidden (build warning), never
   rendered without width/height.

Generated from the same data: `SoftwareApplication`, `BreadcrumbList`,
`FAQPage` (the visible FAQ text, verbatim) and `VideoObject` JSON-LD in one
`@graph`. Every store link goes through `storeLink()` in `src/lib/extensions.ts`,
which adds `utm_source=lamill.io&utm_medium=landing&utm_campaign=<slug>`.

## Deploy

**Vercel**, auto-deploying from `main` → **[lamill.io](https://lamill.io)**. The
site is SSR: nitro emits the Vercel Build Output API (`.vercel/output`).
`vercel.json` sets the build/install commands and `NITRO_PRESET=vercel`. Custom
domain `lamill.io` is set in the Vercel Domains panel.
