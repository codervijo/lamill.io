# AI Agent Context — lamill.io

## What this project is
Marketing / landing site for LaMill (an engineering studio brand), plus a `/work`
portfolio of case studies, a `/notes` namespace for LaMill's own technical writing,
and a small "AI Tools" sub-app (Text Generator, Image Analyzer placeholders) under
`/aitools`. 39 pages are public today: 11 static + 28 published `/work/$slug`
leaves. (3 more work slugs are drafts — they resolve by direct URL but are absent
from `/work` and the sitemap.) `docs/architecture.md` is the page inventory of record.

The current implementation was designed in [Lovable](https://lovable.dev) and
absorbed into this repo on 2026-06-28, replacing the previous React 18 + Vite +
React Router SPA. The Lovable git sync was **severed** — this repo
(`codervijo/lamill.io`) is now canonical. The original Lovable project still
exists at `codervijo/lamill-modernization` if its history is ever needed.

## Stack
- **TanStack Start** (SSR) — `@tanstack/react-start` + `@tanstack/react-router`
  (file-based routing), built on **Vite** with **nitro** as the server builder.
- React 19 + TypeScript.
- **Tailwind CSS v4** (`@tailwindcss/vite`) + **shadcn/ui** (Radix primitives in
  `src/components/ui/`). Design tokens / theme live in `src/styles.css`.
- Icons: `lucide-react`. Forms: `react-hook-form` + `zod` (available; the contact
  form is currently uncontrolled/local-state).
- Package manager: **pnpm** (portfolio convention + parent Makefile). Lovable
  shipped a `bun.lock`/`bunfig.toml`; those were dropped during the move.
- Vite config is provided by `@lovable.dev/vite-tanstack-config` (see Known issues).

## Project structure
File-based routing — every `.tsx` in `src/routes/` is a route. Do **not** create
`src/pages/`. `src/routes/__root.tsx` is the only root layout; `routeTree.gen.ts`
is auto-generated by the router plugin on dev/build (don't hand-edit).

- `src/routes/__root.tsx` — app shell (HTML document, error/404 boundaries, providers)
- `src/routes/index.tsx` — `/` home
- `src/routes/services.tsx` — `/services`
- `src/routes/web-systems.tsx` — `/web-systems`
- `src/routes/content.tsx` — `/content` (the content-production *service*, not our own writing)
- `src/routes/contact.tsx` — `/contact` (local-state form, no backend yet)
- `src/routes/work/index.tsx` — `/work` portfolio index (published entries only)
- `src/routes/work/$slug.tsx` — `/work/:slug` case-study template (loader + `notFound()`)
- `src/routes/notes/index.tsx` — `/notes` index of LaMill's own technical writing
- `src/routes/notes/yocto-vs-buildroot.tsx` — `/notes/yocto-vs-buildroot` (article bodies
  are bespoke routes; only their metadata lives in `src/content/notes.ts`)
- `src/routes/aitools/index.tsx` — `/aitools` landing
- `src/routes/aitools/text-generator.tsx` — `/aitools/text-generator`
- `src/routes/aitools/image-analyzer.tsx` — `/aitools/image-analyzer`
- `src/content/work/*.ts` — one typed `WorkEntry` per case study (31 files, 28
  `published` + 3 `draft`); `src/content/notes.ts` — note metadata
- `src/components/site-shell.tsx` — `SiteShell` (nav + footer) and `PageHeader`
- `src/components/ui/` — shadcn/ui component library
- `src/router.tsx`, `src/server.ts`, `src/start.ts` — router + SSR entry/middleware
- `src/lib/content.ts` — zod content schema + `import.meta.glob` collection loader
  (`getAllWork()` filters drafts; `getWorkBySlug()` does **not** — see Known issues)
- `src/lib/` — also `utils.ts` (cn helper) + Lovable error-reporting/capture (see Known issues)
- `src/hooks/` — `use-mobile.tsx`
- `src/assets/` — imported images (e.g. `hero-sphere.jpg`)
- `scripts/og.mjs` — deterministic OG-image generator (`pnpm run og`)
- `public/` — static assets, hand-maintained `sitemap.xml` / `robots.txt`, and the
  IndexNow key (`f19d828…​.txt`); served as-is
- `docs/` — `prd.md`, `CLAUDE.md`, `Prompts.md`, `growth.md`, `content-authoring.md`,
  `architecture.md` (content plan / site map: hubs vs. leaves, page inventory,
  per-hub content roles)

## How to run
Builds and dev runs go through the **parent Makefile** at `../Makefile` (i.e.
`sites/Makefile`), which runs inside the project's Docker dev container. From `sites/`:

```sh
make buildsh                 # enter docker dev container
make run proj=lamill.io      # pnpm install + pnpm dev (vite dev → TanStack Start)
make test proj=lamill.io     # pnpm install + pnpm build (no test script defined)
```

Host equivalents (per `package.json`): `pnpm install`, `pnpm dev`, `pnpm build`,
`pnpm preview`, `pnpm lint`, `pnpm format`. The project-standard path is the
parent Makefile; don't run pnpm directly on the host.

`dev` is `vite dev` (TanStack Start needs the `dev` subcommand — the old SPA used
bare `vite`). There is no `pnpm test` script.

**One-off scripts (e.g. `pnpm run og`)** run inside the shared dev container, not on
the host: `node_modules` is root-owned and node/pnpm live under **Volta**
(`/root/.volta/bin`, not on the default PATH). Recipe:

```sh
docker exec funny_shannon bash -lc \
  'export PATH=/root/.volta/bin:$PATH; cd /usr/src/app/lamill.io && pnpm install && pnpm run og'
# then restore host ownership on any tracked files root touched:
docker exec funny_shannon chown 1000:1000 /usr/src/app/lamill.io/public/og-image.png
```

(`funny_shannon` = the running `sites1` container; `docker` works without sudo.)

## Key conventions
- New code: functional React + TypeScript, Tailwind utility classes, shadcn/ui
  components. Match the existing dark / monosp'd aesthetic (`font-mono` kickers
  like `// Services`, `glow-text` accent, `grid-bg` backgrounds).
- Wrap page bodies in `<SiteShell>`; use `<PageHeader kicker title intro />` for
  page heroes. Internal nav uses TanStack `<Link to="…">` (typed — routes must
  exist in `routeTree.gen.ts`).
- Path alias `@/` → `src/` (configured in `tsconfig.json` + the Vite config).
- **Canonical domain = apex.** Use `https://lamill.io` (never `www.`) for canonical
  tags, JSON-LD `url`/`logo`, `og:*`, sitemap `<loc>`, robots. This is a fleet-wide
  locked invariant (portfolio v26, operator-locked 2026-06-13; `www`-canonical is
  non-conformant). If a source hands you a `www` URL, switch it to apex.
- **JSON-LD / structured data:** inject via a `{ "script:ld+json": {…object…} }`
  entry in a route's `head().meta` — TanStack-native, renders `<script
  type="application/ld+json">` and is auto-scoped to that route only. The homepage
  Organization (`ProfessionalService`) markup lives in `src/routes/index.tsx`; child
  pages get their own appropriate `@type` (don't put org markup in `__root.tsx`).
- **OG image:** `pnpm run og` (script `og` → `node scripts/og.mjs`) regenerates
  `public/og-image.png` (1200×630) deterministically via satori + `@resvg/resvg-js`
  — no AI/network. Colors are the `src/styles.css` oklch tokens (converted to hex in
  the script); fonts are JetBrains Mono (wordmark) + Inter (tagline) loaded from
  local `@fontsource/*` `.woff` files (satori reads ttf/otf/woff, not woff2).

## Known issues to be aware of
- **Lovable coupling remains at build time.** `vite.config.ts` depends on
  `@lovable.dev/vite-tanstack-config` (bundles tanstackStart/viteReact/tailwind/
  nitro/etc.), and `src/lib/lovable-error-reporting.ts` (imported by `__root.tsx`
  and `server.ts`) posts errors to a Lovable endpoint that no longer applies.
  Tracked follow-up: replace the config wrapper with a plain TanStack Start Vite
  config and neutralize/remove the Lovable error reporter to fully de-Lovable-ify.
- AI Tools pages are pure mocks (`setTimeout`) — no real LLM/vision integration.
  Wire to Claude when implementing for real.
- **Draft work entries 404 — there is no by-URL preview.** `getWorkBySlug()`
  delegates to `getAllWork(opts)`, which filters `status: "draft"` unless
  `{ includeDrafts: true }` is passed; the `/work/$slug` loader does not pass it,
  so the lookup misses and the route throws `notFound()`. Verified 2026-07-31:
  `/work/airsucks`, `/work/caringbeds`, and `/work/mcpscan` all return HTTP 404.
  To preview a draft, set `status: "published"` or thread `includeDrafts` through
  the loader.
- The contact form only sets local state on submit — no backend/email delivery.

## Versioning

This project follows the two-level versioning convention canonical to the
portfolio (see `sites/portfolio/AI_AGENTS.md` for the full statement):

- **`vN`** — major capability tier (SemVer-MAJOR semantics).
- **`vN.X`** — phase letter within a tier (A, B, C, …) for internal slicing.
- **`vN.X.Y`** — numeric sub-phase for follow-up work that lands after `vN.X` shipped.

Track current phase + completed work in `docs/prd.md`.

## Building info

This project's `Makefile` forwards every target to `../Makefile` (the sites/
workspace) which delegates per-stack work to the central builder at
`~/work/projects/builder/`. Common: `make deps`, `make dev`, `make build`. Don't
duplicate build logic per-site.

## Deployment info

Vercel. The Vercel team auto-deploys from this GitHub repo's `main` branch (Git
Integration, configured in the Vercel dashboard). The site is now **SSR**: nitro
auto-detects Vercel and emits the Build Output API (`.vercel/output`).
`vercel.json` sets `buildCommand`/`installCommand` and `NITRO_PRESET=vercel` and
no longer declares `framework: "vite"` (that forced a static-`dist/` SPA build).
Custom domain (`lamill.io`) is configured via the Vercel project's Domains panel.

> **Preset gotcha (not a bug):** a **local** `pnpm build` (no deploy env) falls
> back to the Lovable wrapper's default `cloudflare-module` preset — you'll see
> `.output/server/wrangler.json` + a generated worker name. That's expected, not a
> misconfiguration. On Vercel, `vercel.json`'s `build.env.NITRO_PRESET=vercel`
> (plus Nitro's automatic `VERCEL` env detection) selects the **`vercel`** preset
> instead. Verified 2026-06-29 by reproducing locally: `NITRO_PRESET=vercel pnpm
> build` emits the proper Vercel Build Output API (`.vercel/output/{functions,
> static,config.json}`, `framework: nitro`, route `/(.*) → /__server`) with no CF
> artifact. The **live** Vercel build still wants a real-deploy smoke-test before
> treating SSR-on-Vercel as fully canonical.
